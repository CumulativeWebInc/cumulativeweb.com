Verified Briefs

NEW WORK — built 2026-10-27 for the Meta Global AI Developer Hackathon. Discovery Engine (pre-built) plus a new verified-reasoning layer: Muse Spark 1.3 reasons over a music brief, and a deterministic gate disposes every candidate the model proposes. The model never gets the final word on identity, ISRC or clearance.

How it works

  1. Muse Spark 1.3 (Meta Model API) reasons over the brief and proposes up to 5 candidate tracks, with one sentence of reasoning each. ISRCs are deliberately left out of its prompt, so it cannot fake one into the shortlist.
  2. The caller passes those candidates to the new MCP tool verify_brief_candidates on the Discovery Engine worker. The tool makes no Meta API call and holds no Meta key.
  3. The gate checks each candidate against the worker sync catalog data (machine-data-layer/sync-catalog-data.js, 29 tracks, 18 verified ISRCs): PASS = catalog match + verified ISRC; FLAG = catalog match without a verified ISRC; DROP = no catalog match.
  4. Only PASS candidates reach the verified shortlist.

Known gap, stated not hidden: cuefinder audit counts 19 verified ISRCs; this file counts 18. The one-track difference is unreconciled. v1 gates on this file only.
